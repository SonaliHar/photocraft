## Review (Claude, Oct 13, 2026)

**Approved.** Read `ai.rs`, the `Session` changes, the test list and this receipt against SPEC v1.1 §1, TASKS PC-01 and AGENTS.md.

- Matches the spec: object-safe `AiProvider: Send + Sync`, no network or new dependencies, provider stored as `Option<Arc<dyn AiProvider>>` on `Session` (`Default` gives `None`), exact "Craft AI Manager isn't running" text, B08 provenance fields in `AiResult`.
- Never-crash rules hold: crate-level `deny(clippy::unwrap_used, …)` applies; `sample_count` uses `try_from` / `checked_mul` with a size cap; request coverage is checked for finite 0–1 values; mismatched result window, format or length is an error, not a panic.
- Provider-supplied progress is safe: `JobCtx::progress` ignores non-finite values and clamps to 0–1.
- Cancellation is checked before submit, around every provider call and every 10 ms while waiting, and `cancel` is sent even when the remote cancel fails. On wasm the helper returns a clear "not available" error instead of blocking, which is right since no provider exists there.
- Tests cover every case the task listed, plus invalid requests, wrong window, provider errors and cancel during a failed poll.

**Follow-ups (not blocking, carried into PC-02):**
1. `run_to_completion` doesn't check that the **result pixels are finite**. Data from a provider is outside input; PC-02 must reject (or clamp, with a test) NaN/inf pixels before writing them into a layer.
2. There is no overall time limit while a job stays `Running`; the user can always cancel, and PC-03 adds HTTP timeouts, so this is acceptable for M1.
3. The receipt's **Base** line says `f0d54fb`; the branch was rebased onto `721df5c`. Cosmetic.
